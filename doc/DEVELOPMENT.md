# gosoul 开发方向（v2 定稿）

> 2026-08 团队确认。本文件是唯一方向基准；实现与本文冲突时以本文为准。

## 一句话

**Majsoul 服务端完整平替**：客户端零改动（MITM 代理接入），用户面 + GM 面 API 全量还原，
Go 实现，技术分享与二次开发为基调，不做页面 UI、不做商业化运维。

## 做什么（做完整，分阶段）

核心闭环（P0）→ 成长系统（P1）→ 运营系统（P2）→ 外围（P3）

| 优先级 | 范围 |
|---|---|
| P0 | 账号（登录/注册/自动注册）、大厅（房间/匹配）、对局（四麻/引擎/AI）、牌谱 |
| P1 | 角色/皮肤、货币（金币/钻/票）、抽奖/开箱、成就 |
| P2 | 商店/道具、活动框架、公告、任务；GM 面覆盖上述 |
| P3 | 三麻、定制赛、观战 |

## 不做什么

- ❌ 页面 UI（GM/用户端均后置，API 是一等公民）
- ❌ 充值/防沉迷/实名（API 面留占位）
- ❌ 多区部署/负载均衡/商业化运维
- ❌ 客户端魔改/资源替换

## 工程原则（团队共识）

1. **复用优先**：有成熟第三方库绝不用手搓（例：MITM → goproxy、wire → protowire）。
   自实现仅限协议 wire/XOR 这类必要领域。
2. **纯领域设计**：引擎/服务无 I/O 依赖，随机性与决策经接口注入；单测零外部依赖。
3. **以客户端 API 面为准**：功能清单 = 客户端实际调用的 RPC + GM 管理需求，不臆造。
4. **存储抽象**：仓储接口隔离，SQLite 起步，可换 Postgres。
5. **协议热更新**：liqi.proto/liqi.json 内嵌，更新即重编译。

## 架构基准

```
接入   gateway(基于 goproxy, 自持 CA)
服务   lobby + user(character/achievement/shop/lottery/activity) + admin(GM API)
对局   game(会话) → engine(纯规则) + ai(Player接口, 可挂 mjai) + deal(测试)
协议   protocol(五层封包/XOR/动态消息/路由表)
数据   storage(SQLite, 版本化迁移)
```
