# gosoul 方向声明 (VISION)

> 状态：2026-08 经团队确认（第二版）。本文件优先级高于实现细节。

## 是什么

一个 **Majsoul(雀魂) 服务端的完整平替实现**，用 Go 从零还原，覆盖官方后端的全部能力面：

- 用户面 API：登录/注册、角色/装扮、抽奖/开箱、成就系统、商店/货币、活动、房间/匹配、对局、牌谱 — 客户端实际调用的每个 RPC 都有正确响应。
- GM 面 API：账号管理、资源/角色发放、系统配置、运营操作。**页面 UI 后置**，API 是一等公民。
- 代理软件（gateway）：玩家开代理 → 本机官服流量被引到指定服务器，客户端零改动。

## 核心价值

1. **协议与系统面的完整还原**：不止对局协议，而是账号/商品/成就/抽奖等业务 API 面的全量对话层。
2. **日麻规则引擎完整正确**：全役种（含双立直、数え役满）、三麻，单测背书。
3. **可运行的闭合系统**：代理 → 登录注册 → 大厅 → 抽角色 → 建房 → 对局 → 牌谱，全链路可用。
4. **工程化示范**：纯领域 + 接口注入、存储抽象、零 cgo、单二进制、可扩展。

## 功能分级（平替的落点）

- **P0 核心闭环**：账号(登录/注册/自动注册)、大厅(房间/匹配/好友占位)、对局(四麻/引擎/AI)、牌谱
- **P1 成长系统**：角色/皮肤持有与解锁、货币(金币/钻/皮肤票)、抽奖/开箱、成就
- **P2 运营系统**：商店/道具、活动框架、公告、任务；GM 管理面覆盖上述全部
- **P3 外围**：三麻、比赛/定制赛、观战

驱动原则：功能**以客户端 API 面为准**（参考实现 + 抓包可观测 RPC），不做官方没有的臆造系统。

## 边界（仍不做）

- ❌ 页面 UI（GM 台与用户端均后置，API 先行）
- ❌ 充值/防沉迷/实名等真实合规系统（API 面保留占位）
- ❌ 多区部署/负载均衡/商业化运维
- ❌ 客户端魔改/资源替换

## 架构

```
接入层   gateway（代理软件：域名劫持 + TLS 终结 + 透传）
服务层   用户面: lobby + user(character/achievement/shop/lottery/activity) + paipu
        GM 面:  admin API（账号/资源/配置/运营）
对局层   game(会话) → engine(纯规则) + ai + deal(测试工具)
协议层   protocol(五层封包/XOR/动态消息/路由表)
数据层   storage(interface) → SQLite 起步，预留迁移
```

## 路线图

1. ✅ 协议层 + 参考实现逐字节对齐单测
