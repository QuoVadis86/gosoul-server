# ADR-0001: gosoul 技术栈与分层决策

状态：接受 | 日期：2026-08 | 决策者：架构组

## 背景

gosoul 是一个 Majsoul 协议兼容的日麻私服，目标形态为"玩家侧 MITM 代理 + 本地核心服务 + GM 管理台"。协议层已通过运行时代码与上游参考实现对齐，本项目负责正确的业务实现与工程化。

## 决策

### D1 语言与运行时
Go 1.26（标准库 `log/slog` 日志、`net/http` 增强路由）。多前端共存、部署为单二进制。

### D2 存储
- 默认 **SQLite**（`modernc.org/sqlite`，纯 Go 无 cgo）。
- 所有持久化经由 `internal/storage` 接口访问；接口按聚合设计（账户、对局记录、牌山预设、系统配置）。
- 预留 Postgres 适配器（配置切换），不在本期实现。
- 不使用 ORM；采用 `database/sql` + 版本化迁移 runner（`internal/storage/migrate`），迁移以 SQL 文件形式随二进制内嵌。

### D3 ~~管理端 API~~（已废弃）
见 `doc/VISION.md`：不做 GM 管理台。2026-08 方向收缩后移除 `internal/admin` 与 `web/`。

### D4 ~~管理端 UI~~（已废弃）
同上，Vue 3 + Element Plus 的设计封存，不再实现。

### D5 玩家侧代理
基于 **elazarl/goproxy** 构建：自持 CA（注入 goproxy 全局 MITM 签名）、对游戏域名
（`*.maj-soul.com` 等）做 TLS 终结与本地应答，其余域名以盲隧道透传。不手写 TLS/隧道
逻辑（2026-08 曾手搓，后按复用原则替换）。玩家只需启动代理程序并信任 CA，客户端零改动。

### D6 协议层
运行时用 `bufbuild/protocompile` 编译内嵌 `liqi.proto`，`dynamicpb` 编解码；路由表取自内嵌 `liqi.json`。与上游 JS 参考实现同构，便于协议演进对照。

### D7 游戏引擎纯净性
引擎（`internal/game/engine`）保持领域纯净：无 I/O、无随机源私有语义；牌山由 `engine.WallFactory` 注入，AI 由 `ai.Player` 注入。单测不依赖任何服务组件。

## 后果
- 单二进制 + 内嵌 SPA 与数据：部署为零配置。
- 协议热更新：替换 `data/liqi.proto` + `liqi.json` 重新编译即生效。
- 约束：跨实例扩展需引入分布式存储（本期明确不做）。
